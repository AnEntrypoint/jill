# CARRY-FORWARD: facts measured on this project (jev-local landing page)

Each line: the fact, the measurement that established it, the move it changed.

1. A 390 px iframe with a 3000 px height reports clientWidth 375 because a 15 px vertical scrollbar takes width; judge horizontal overflow by scrollWidth against clientWidth in the same frame, not by the iframe width. Measured: 390 px frame, scrollWidth 375 = clientWidth 375. Changed the overflow check (sections 9 and 11).
2. An inline SVG with `preserveAspectRatio="none"` and a 640-unit viewBox keeps rect widths proportional at any container width: rect 530 of 640 renders at 284 px in a 343 px container, with the 5.3 : 3.9 : 6.4 ratio kept. Measured via getBoundingClientRect on the svg and the rect width attributes. Changed M3 (bars at true proportion).
3. `max-width: 66ch` on a 15 px figcaption renders about 566 px at 1280 px, because `ch` is measured in the element's own font; the page column is 672 px. Changing it to 50ch gave 429 px. Measured with getBoundingClientRect. Changed the Bringhurst figcaption fix (R4).
4. A `role="status"` live region that is `display: none` while empty is removed from the accessibility tree; the empty-and-zero-height form (`margin: 0; height: 0`) keeps it in the DOM. Argued by the Mace critic, not tested with assistive technology. Changed the status line (R3).
5. In this headless Chromium build, `--blink-settings=preferredColorScheme=2` did not switch the `prefers-color-scheme` media query; the screenshot was byte-identical to the light one (114492 bytes). Dark mode was verified by a scratch copy with the media query replaced by `@media all`. Changed the dark-mode check method.
6. `--virtual-time-budget` with `--allow-file-access-from-files` and `--dump-dom` lets a file:// page script measure its own iframe layout, so layout checks run without a browser automation tool. Measured: the iframe script returned scrollWidth, bar widths and status height. Changed the measurement procedure (section 9).
7. A headless full-page screenshot needs a window height at least as tall as the page: a 1500 px window clipped the content and a 3700 px window captured it whole. Measured by visual check. Changed the render step.
8. A line-length cap written in `ch` on the body paragraph (`p { max-width: 66ch }`) gives about 75 characters per line at 17 px on desktop, which matched the critic's measure target. Measured by the Bringhurst critic's R3 and R4 reports, not re-measured here. Changed the body measure (R3).
9. The skill file SKILL.md changed during the run (mtime 06:48, after the agent read it at about 06:33) and gained extra speed numbers (16-question chunk, cold 10-question run). The page quotes only the README's figures, as the brief asked. Check the README's mtime before quoting any figure from a skill file. Changed the source choice for the Speed section.
