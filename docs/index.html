jill

jill answers small typed questions about a piece of text, using a claude-haiku-5-5 subagent in place of TypeSafe's Jev, a cloud decision model.

npx skills add AnEntrypoint/jill

Needs Node.js for npx. jill is one skill in the jill repository. Run it in an agent that has an Agent tool, such as Claude Code, and ask for it, for example: Use jill: which lane should this message go in, and does a person need to see it now?

The agent dispatches the Haiku subagents itself. In Claude Code you can add it as a plugin instead: /plugin marketplace add AnEntrypoint/jill, then /plugin install jill@jill.

How it works

  1. Prepare chunks

    Group the questions that share one state into chunks of up to eight.

  2. Dispatch Haiku subagents in parallel

    Send one subagent per chunk on the claude-haiku-5-5 model (model: "haiku"), all in one message. Each uses the read-only Explore agent type, which cannot write files, at low effort, and replies with JSON only.

  3. Merge

    Check that every question has exactly one answer, that choices are real options and that scores sit in range. A noul answer must be yes or no, which becomes true or false. Anything invalid is flagged, never guessed. Below 0.6 confidence, escalate the answer or route it to a person.

Three question types

Each question has one of three types.

Choice

Pick one option.

{
  "id": "lane",
  "type": "choice",
  "question": "Which lane?",
  "options": [
    "billing",
    "shipping",
    "support",
    "spam"
  ]
}

Score

Place the state (the text being judged) on a scale. The ends are the question's own, for example 0 for not urgent and 1 for most urgent.

{
  "id": "urgency",
  "type": "score",
  "question": "How urgent?",
  "scale": [0, 1]
}

Noul (yes or no)

Is a yes or no statement true of the state?

{
  "id": "refund",
  "type": "noul",
  "question": "Asks for a refund."
}

Example reply

{
  "id": "lane",
  "value": "billing",
  "confidence": 0.97
}

One answer, in the shape the skill documents. Every answer carries its own confidence from 0 to 1. Below 0.6, the state did not settle the question, so escalate it or route it to a person. This one is an example, not a measured result.

A failed answer

{
  "id": "lane",
  "value": null,
  "confidence": 0,
  "error": "not_an_option"
}

An answer that is missing or invalid comes back unknown, with an error field. The caller never guesses. If a chunk's reply fails to parse, the skill re-dispatches that chunk once; if it still fails, those answers stay unknown and the caller takes its default path.

Eleven ready-made policies

Question sets for common decisions, in references/policies.md, ready to paste as a question list. To write your own, give each question an id and pick one type: choice, score or noul.

  • Model routing: the cheapest model tier good enough for a turn. Risky work never goes to the cheapest tier.
  • Skill selection: which installed skill a turn needs, or none.
  • Triage: what kind of message it is, how urgent, and whether a person must see it now.
  • Mailbox lanes: which lane a message belongs in, and whether it deserves attention.
  • Memory filter: which retrieved passages help answer the current question.
  • Turn selection: which turns to keep when a transcript has to be cut.
  • Injection screen: whether web or tool output tries to instruct an agent.
  • Command gate: whether a shell command is safe to run without review.
  • Pull request risk: how risky a change is, and whether a senior engineer must review it.
  • Incident severity: how bad an incident is, and whether on-call must be paged now.
  • Personal data: whether a text holds personal or sensitive information, and whether it can be shared.

Worked example: triage

[
  {
    "id": "kind",
    "type": "choice",
    "question": "What kind is it?",
    "options": [
      "bug",
      "question",
      "request",
      "billing",
      "other"
    ]
  },
  {
    "id": "urgency",
    "type": "score",
    "question": "How urgent is it?",
    "scale": [0, 1]
  },
  {
    "id": "human",
    "type": "noul",
    "question": "Needs a person now."
  }
]

Reworded from policies.md to fit a phone. The exact triage set is in that file. The caller maps the answers to actions itself.

Speed

The timings in the project README are single samples, with about a second of noise, so read them as rough.

One 16-question chunk took 8.5 s at default effort, a single sample. The skill keeps each chunk at eight questions or fewer.

Identical decisions on the same state are reused within a conversation, so repeats cost no model call. The skill's speed and token notes list the other measurements.
